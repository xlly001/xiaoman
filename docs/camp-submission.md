# 【第二期结营作业】我做了小满助手

## 一、Agent介绍

**Agent名称：** 小满（Xiaoman）

**解决的问题：**

手机上的日常小事被拆散在几十个 App 里：查快递要开购物 App，记事情要开备忘录，改设置要翻系统菜单。通用聊天助手只能“告诉你怎么做”，不能“替你做”；把手机整个交给云端 Agent，又不放心。

小满要解决的是三件事：

1. **记得住**：你说过的偏好、地址、常用单号，它写进本地记忆，下次直接使用。
2. **做得到**：通过 Android 无障碍服务读取屏幕、点击、输入，真正替你操作其他 App。
3. **管得住**：付款、发送、删除等高危动作必须经过独立于模型的 Sentinel 审核，模型绕不过去。

**一句话介绍：**

> 小满是一个住在你手机里、会记事、能替你操作 App 的私人 Agent。

**开发方式：** 基于 TRAE 训练营课程开源项目 [aduoge/xiaoman](https://github.com/aduoge/xiaoman)（MIT 协议）做二次开发。原项目提供 Agent 骨架、无障碍操作循环、Sentinel 安全层、记忆与技能基础；本次在此基础上做界面、任务系统、流式回复、语音/识别、评测等改造。

**当前发行版：** Android `v0.1.2`（release APK）。

**和课程原版比，改了什么：**

- **界面：从 5 个基础页面到完整 App 壳**。原版只有聊天 / 技能 / 记忆 / MCP / 设置；现在改成 Open Muse 风格，底部输入与导航合并为全局 Dock，5 个页签（聊天 / 能力 / 任务 / 记忆 / 小满），新增任务页、任务详情、日记、全局搜索、常用指令、中英文切换。
- **聊天：从单轮工具调用到可回看的流式对话**。原版没有会话持久化和流式回复；现在会话本地保存（默认 500 条）、SSE 流式渲染、停止立即取消挂起请求，并新增每条回复单独朗读、消息长按选区复制。
- **审批：从聊天页卡片到全局胶囊灵动岛**。原版审批卡只在聊天页底部；现在「小满」胶囊本身向下展开成审批卡，App 内任何页签、任务详情、搜索页都能看到；小满在后台操作其他 App 时，无障碍悬浮层也会展开审批卡（拒绝 / 允许一次 / 本次任务都允许）。
- **任务：从一回合跑完到可排队、可续跑**。原版 `phone_task` 在聊天回合内同步执行；现在有任务队列（串行、暂停/继续/取消、最多 20 个未完成任务）、每步检查点、杀进程重启后从第 N 步续跑、任务独立子对话。
- **语音与识别：从 0 到 3 个引擎**。原版没有 TTS / ASR / OCR；现在接入三套可插拔引擎，DeepSeek 默认走官方 `/v1/tools/{asr,tts,ocr}` 并复用聊天 Key，其它服务商回退系统能力，设置页可切换；ASR / TTS / OCR 还能分别指定引擎，例如 ASR 用 DeepSeek、TTS 用系统内置。
- **技能：从“只能看”到“手机上能写”**。原版技能只能查看、从电脑推送；现在保留内置技能只读，新增用户技能新建、修改、删除；保存前顶部胶囊直接给出「取消 / 确认」，说“继续”也算确认，同名用户技能可覆盖内置技能。
- **记忆：从“搜索/删除”到可新建、可编辑**。原版记忆页只有搜索、查看、删除；现在追加新建与编辑，文件仍是 Basic Memory Markdown。
- **模型配置：从手填到可发现**。原版手填 Base URL / 模型 / Key；现在有 9 个厂商预设、拉取 `/models`、读取厂商元数据、聊天/操作模型自检与展开配置。
- **工程：从能跑到可验证**。新增 `eval` 评测 15 个场景、任务队列/检查点/流式/媒体单测、假 LLM 与媒体验收脚本；模拟器端到端验收了技能创建 → 胶囊确认 → `SKILL.md` 落盘，以及任务队列/断点/媒体/中英文。

**代码层面**：新增 26 个源文件（21 个 App 文件、`core-api/Media.kt`、3 个 `core-llm` 文件、`core-skills/UserSkillStore.kt`），改动 30+ 个现有文件；`core-sentinel`、`core-memory`、`core-mcp` 未改，安全策略与记忆格式保持不变。
