# 小满聊天与任务界面

本轮参考 Open Muse 的信息层级，在 Android Compose 中独立实现。参考源码为 `chyroc/open-muse` 提交 `051a2f0`，没有搬用其头像或前端代码。

## 二次开发：Open Muse 视觉与便捷功能（2026-11-15）

在 main 课程版之上把视觉进一步对齐 Open Muse 的聊天样式，并补了日常高频能力：

| 位置 | Open Muse 参考 | 小满实现 |
|---|---|---|
| 纸面 | `--chat-paper: #fcfcfc` | 浅色 `background #FCFCFC`，深色 `#000000` |
| 气泡 | 助手 `--chat-gray: #eaeaeb`、用户 `--chat-blue: #c9e5ff`、22px 圆角、无尾巴 | 助手 `surfaceContainer`、用户 `primaryContainer`，统一 22dp 圆角 |
| 强调色 | `#1a62d6` | `primary #1A62D6`，只用于状态、选中和发送等关键动作 |
| 顶部 | 居中名字胶囊 + 状态副标题 + 两侧玻璃圆钮 | 居中「小满」胶囊 + 就绪/处理中/等你确认副标题；左侧齿轮进入设置、右侧更多菜单 |
| 输入区 | 浅灰悬浮输入坞 | 一体 Dock 的输入行：加号、输入框、发送（有内容时）、麦克风 |
| 导航 | 侧栏（Web） | Android 改为底部一体 Dock：输入框在上、页签在下，选中项用浅蓝底和蓝色图标 |

新增交互：

- **全局 Dock**：输入框和底部导航合并为同一张悬浮卡片，聊天、能力、任务、记忆、小满、设置页都显示；卡片外圈不画背景、保持透明，输入框本身近不透明以保证可读；键盘打开时只保留输入行。
- **导航**：聊天 / 能力 / 任务 / 记忆 / 小满；设置通过聊天页左上角齿轮进入。
- **能力页**：技能与服务合并，顶部「技能 / 服务」分段切换；技能分段保留搜索、新建、刷新、详情、修改、删除，服务分段保留 MCP 勾选、Key、测试与自定义。
- **任务页**：展示全部历史任务，按开始时间倒序；全部/进行中/已完成/未完成筛选；卡片显示目标、状态、步数、开始时间与摘要，点击进入任务详情。
- **任务队列**：右上角「新建任务」打开对话框填写目标，加入 `chat/queue.json`；队列区在筛选条下方显示排队中/已暂停任务，可暂停、继续、取消；同一时刻只跑一个任务，结束后自动取下一条；运行中的任务在详情页可停止。未配置模型时提示先配置，对话框保留输入。
- **断点恢复**：每步写检查点；应用重启后带检查点的任务回到队列，状态显示「排队中 · 重启后继续」，启动完成后从第 N 步继续，任务线程里会出现「应用重启，从第 N 步之后继续」。没有检查点的任务标记为「应用重启，任务中断」；技能流程任务会明确失败而不是重放动作。队列区与历史列表按任务 id 去重，同一任务不会出现两张卡。
- **输入区**：左侧加号打开附件菜单；右侧固定语音按钮；输入为空时隐藏发送按钮，忙时显示停止；输入框高度压到 38dp 起。
- **附件**：加号菜单含拍照、相册、文件；图片按最长边 1280px 转 PNG 随消息发给模型，文本文件（≤20KB）内联进消息；用户气泡显示「图片 × N」。
- **常用指令**：首页默认 6 条、最多 8 条；卡片右上角可编辑/删除，点卡片把提示词填入 Dock，不自动发送。
- **会话历史**：聊天记录写入 `chat/history.json`，重启恢复；更多菜单「清空会话」会二次确认，同时清空任务子对话；设置页可把保留条数调为 50–2000。
- **任务子对话**：派给小满的手机任务单独建线程，主对话只在文本下保留一张任务卡（进行中/已完成/未完成），不额外显示会话列表；点卡片进入任务详情。任务详情本身也是一段对话，底部 Dock 的输入框会发到该任务线程，回复留在该线程；处理过程默认展开。任务存 `chat/tasks.json`。
- **搜索**：右上角菜单第一项「搜索」，搜主对话和所有任务子对话；任务结果可直接进入详情。
- **小满日记**：底部「小满」页，按天一张卡片，横向滑动、圆点指示；记录任务完成/失败与记忆更新，存 `diary/diary.json`。
- **语音输入**：系统 `SpeechRecognizer`，只接受最终结果；录音权限、无识别服务、无匹配、网络错误都有对应文案。
- **模型自检**：聊天模型发文本，操作模型附带 1×1 PNG；成功显示延迟，失败按 401/403、404、429、400（图片）和网络错误分类。
- **技能/记忆管理**：技能页支持搜索、详情、新建和一句话修改；记忆页支持新建、编辑、删除。
- **国际化**：新增文案全部进入 `values/strings.xml` 与 `values-en/strings.xml`，当前 388 个 key 两边一致；任务进度、附件、搜索、任务、日记、悬浮层、内置能力与「等待确认」状态都走资源；设置页可切换跟随系统/简体中文/English。
- **紧凑布局**：常用指令卡最小高度 108dp、内边距 11dp；聊天列表只留 4dp 上下内边距，消息底部对齐；Dock 合并后不再有独立的导航空白带。
- **设置页**：聊天页左上角齿轮进入；服务商下拉 + 一个 Key + 「获取可用模型」；优先采用厂商返回的上下文/最大输出/图片能力元数据；模型行展开可改显示名、最大输出、上下文、Temperature、图片支持，编辑已选模型会回写实际配置；可分别设为聊天/操作模型并保存全部模型。另有主题与语言（即时生效）、语音自动发送、通知开关、请求超时、会话保留条数、无障碍入口、清空会话/轨迹、版本与本地数据说明。
- **悬浮层**：任务运行时显示当前步骤与停止按钮；没有步骤文本时使用应用名作兜底，读屏描述走中英文资源。
- **内置能力（TTS / ASR / OCR）**：设置页「内置能力」卡片可选「跟随服务商 / DeepSeek 官方 / 系统内置」，并显示当前生效引擎与工具端点；用 DeepSeek 模型时默认走官方 `/v1/tools/{asr,tts,ocr}`。聊天页麦克风按钮由「开始录音」变为「停止并识别」；附件菜单第四项是「识别图中文字」，识别的文字并入输入框而不是当附件发出；打开「自动朗读回复」后，最终回复整段朗读一次（不朗读流式增量）。音色可选「海星（女声）/ 暗潮（男声）」，OCR 可选「纯文字 / 版面识别」。
- **视觉**：淡蓝渐变背景、白色大圆角卡片、底部一体 Dock；不使用参考应用的角色形象与版权素材。

验收状态：`assembleDebug`、`lintDebug` 与 `core-llm`、`core-agent`、`core-skills`、`app` 单测均通过。已在 Pixel 6 / Android 15（API 35）x86_64 模拟器（WHPX）上安装 debug APK 验收：

- 快捷指令：新增一条后写入 `chat/quick-commands.json`，杀进程重开仍在；点卡片只填入输入框，不自动发送；默认 6 条填满首屏。
- 会话历史：发一条消息后写入 `chat/history.json`，杀进程重开仍显示；「清空会话」后文件删除、界面回到首页。
- 记忆：新建后写入 `memory/TestNote.md`，内容为合法 Basic Memory frontmatter。
- 语音：点击麦克风进入「正在听，请说话…」，App 未崩溃。
- 模型目录：手动添加 `abc` → 展开默认配置 → 设为聊天/操作 → 保存提示「已保存 · 1 个模型」→ 杀进程重开仍在；`settings.xml` 可见完整 `provider.models`。
- 主题/语言：选择深色立即变暗且重启保持；选择 English 立即切换界面，选择跟随系统立即恢复中文。

- 任务子对话：注入 `chat/tasks.json` 与主对话 `TaskEntry` 后，主对话显示任务卡；点击进入详情，步骤默认展开；搜索 `App` 命中任务并可直达详情。

## 第一轮：交互结构参考

| 参考位置 | 可借鉴的交互 | 小满的实现 |
|---|---|---|
| `src/ChatUI.tsx` 的 ChatHeader | 名称旁显示简短状态 | 小满标题、就绪/处理中/等你确认 |
| `src/chat.css` | 留白、轻量气泡、清楚的主次 | 二次开发后改为 Open Muse 蓝灰主题，浅色和深色模式；跟随系统字体缩放 |
| `src/styles.css` 的 activity-toggle | 过程按需展开 | 连续进度记录收进“处理过程”，问题、错误和回答保持可见 |
| `src/message-cards.css` | 结果与普通过程分开呈现 | 助手结果用独立卡片，支持基础粗体和列表 |

确认卡片固定在聊天底部，自动收起键盘；优先展示“暂不允许”和“允许一次”，“同类操作都允许”放在更多选项。批准后仍须回到目标 App，并重新核对页面；没有取消原有确认规则。

悬浮任务条只在小满页面之外显示，点击文字可返回任务；停止按钮继续保留，执行手势和截图时仍临时隐藏悬浮条。

首页“选一本笔记本”只填写一句可编辑的中文，需要用户点击发送才执行。购物默认规则由助手承担：普通规格、数量1、含运费预算、核对结算后停止。它们是模型指引，支付前仍依赖独立确认机制，不能把提示词当成硬性权限控制。

真机验收应覆盖：大字体布局、中文发送、过程展开、确认按钮、返回目标 App、停止、真实结果。Open Muse 是 Web/Capacitor UI，小满是原生 Compose；本轮借鉴交互结构，保留小满的应用架构。

## 本轮实测（2026年11月2日）

在 vivo V2141A / Android 14 上安装本轮 debug APK，保留系统字体缩放 1.25001 和显示密度 704。直接点击首页中文示例，再点击发送：

> 帮我在淘宝挑一本20元以内的A5笔记本，选好后给我确认。

任务 `app-20261102-225742-pc64` 成功执行10个手机动作，经过2次“允许一次”，进入确认订单页。页面和回复均为【牛皮】A5·1本、每本72页、数量1、2.40元包邮；没有提交订单或支付，也没有遇到验证码。该账号已有上一轮淘宝路径记忆，价格包含当次平台优惠，不代表全新账号的通用价格或所有购物场景均已验证。

真机已检查首页、中文发送、过程展开和收起、底部确认卡片、批准后返回淘宝、结果卡片、小满前台不显示任务悬浮条。深色模式和其他机型未做本轮真机验收。

`test :app:assembleDebug` 通过，共226次JUnit测试执行，0失败、0错误（包含debug/release，非226个独立场景）。“10万+人付款”导致的多余确认仍存在，不能当成已修复；此处保留为进阶开发题。
